# 🛠️ 第三階段詳解：接上「工具」（Function Calling / MCP）

在前兩個階段，我們已經給了 AI 大腦、記憶與人設，但它依然被關在沒有窗戶的房間裡——**只能「動口」、不能「動手」**。

到了第三階段，我們要幫這顆聰明的大腦裝上「手腳」，讓它能夠查詢即時天氣、搜尋 Google、讀取你的資料庫，甚至幫你寄出 Email。在技術上，這個機制稱為 **Function Calling（函式呼叫 / 工具使用）**，以及近年最火紅的標準協定 **MCP（Model Context Protocol）**。

---

## 1. 破除迷思：AI 其實「不會」自己按按鈕！

初學者最常誤會：「接上工具，是不是代表 AI 自己打開瀏覽器去查資料？」

**答案是否定的！** AI 本質上依然只是一個「接收文字、吐出文字」的模型，它沒有手，也碰不到你的電腦或網路。

### 🍲 餐廳廚房的比喻（工具版）

* **大廚（LLM）：** 依然待在廚房裡，不能出來，也不會自己去買菜。
* **採購員（你的主程式）：** 站在廚房門口，負責跑腿（連網查資料、操作資料庫、寄信）。
* **工具清單（Tools）：** 貼在廚房牆上的一張表，上面寫著：「如果你需要知道外面天氣，請寫一張紙條給我，格式是 `查天氣(城市名稱)`。」

當客人問：「台北現在會下雨嗎？」大廚知道自己不知道，於是**他不直接回答客人**，而是遞出一張寫著 `查天氣("台北")` 的紙條給採購員。採購員跑出去查完回來，把結果告訴大廚，大廚再轉頭用親切的語氣回答客人！

---

## 2. 完整運作流程：一場「傳紙條」的接力賽

當你問 AI 一個需要外部資料的問題時，背後其實發生了 **4 個步驟（一來一回共呼叫兩次 API）**：

1. **人類發問 + 附上工具說明書：**
   你的程式把問題「台北現在幾度？」連同一份「可用工具清單（JSON 格式的說明書）」一起傳給 LLM API。
2. **大腦判斷並回傳「指令紙條」（Function Call）：**
   LLM 讀了說明書，發現自己剛好有 `get_weather`（查天氣）這個工具可以用！於是它暫停回答，吐出一段特定格式的指令：`{"tool": "get_weather", "city": "Taipei"}`。
3. **你的程式真正去執行動作：**
   你的程式收到這張紙條，立刻去呼叫真實的氣象局 API，拿到結果：`"24度，晴時多雲"`。*(💡 真正連網、動手做事的是你的程式，不是 LLM！)*
4. **把結果交回給大腦，產出最終回答：**
   程式把 `"24度，晴時多雲"` 塞回對話紀錄裡，再次傳給 LLM API。這次大腦有了足夠資訊，終於用人類的語言回答你：「台北現在 24 度，天氣晴時多雲，很適合出門喔！」

## 3. 什麼是 MCP（Model Context Protocol）？

隨著大家越來越愛給 AI 裝工具，工程師遇到了一個大麻煩：**「接口不統一」**。

* 如果你想讓 AI 連上 Google Drive，要寫一套專門的接線；
* 想讓它連上 Slack、Notion 或公司資料庫，又要各自寫不同格式的說明書，換一家 AI 模型（例如從 OpenAI 換成 Claude）可能還得重寫，非常痛苦。

為了解決這個問題，Anthropic 推出了 **MCP（模型上下文協定）**，現在已成為整個 AI 業界的通用標準！

### 🔌 USB-C 充電線的比喻

* **沒有 MCP 以前：** 就像早期的手機充電線，Nokia、Sony、iPhone 各用各的插頭，線材完全不通用，開發者累得半死。
* **有了 MCP 以後：** MCP 就像是 **AI 界的 USB-C 統一接口**！只要工具開發商（例如 Google、Notion、GitHub）按照 MCP 標準做好一個「MCP Server（工具插座）」，任何支援 MCP 的 AI（如 Claude、Cursor、各種 Agent 框架）只要「隨插即用」，一秒就能獲得操作該軟體的能力，完全不用重新寫對接程式！

## 4. 第三階段的成果與最後一塊拼圖

恭喜！走到這一步，你的 AI 已經從「只會聊天的書呆子」，進化成「有手有腳、能查詢即時資訊並執行特定動作的幫手」了。

### ⚠️ 距離「真正的 AI Agent」還差最後一步！

目前這個階段，通常還只是**「一問一動」**（你問一句，它用一次工具，然後回答你）。

但如果今天你的任務很複雜，例如：
> *「幫我查明天台北天氣，如果降雨機率超過 $50\%$，就去行事曆把明天的戶外會議取消，並寫信通知所有與會者改為線上會議。」*

這個任務需要**連續使用 3 個不同的工具**，而且「要不要取消會議」還取決於「查天氣的結果」。單純的工具呼叫無法自己決定下一步該做什麼。

## 🎯 本階段總結

**接上工具（Function Calling / MCP）** 讓 LLM 學會了「承認自己不知道，並開出指令紙條請求外部程式協助」，徹底打破了大模型與現實世界的隔閡。

> **下一步預告：** 為了讓 AI 能夠自己拆解複雜任務、連續使用多個工具、遇到錯誤還會自己修正，我們將在**第四階段（最終章）**啟動**「思考與行動迴圈（Agent Loop）」**，見證真正的 **AI Agent** 誕生！
