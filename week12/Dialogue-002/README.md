# 🧠 第一階段詳解：純粹的 LLM API（大腦）

在建構 AI Agent 的路上，**LLM API** 是一切的起點。如果把整個 AI Agent 比喻成一個人，那麼 LLM API 就是他的「大腦」——它擁有極高的智商和海量的知識，但還沒有眼睛、耳朵、手腳，也沒有短期記憶。

這份指南將用最白話的方式，帶你徹底搞懂「純粹的 LLM API」到底是怎麼運作的。

---

## 1. 什麼是 API？（餐廳點餐的比喻）

在理解 LLM API 之前，我們先拆解 **API（Application Programming Interface，應用程式介面）** 這個詞：

* **LLM（大型語言模型）：** 就像是躲在廚房裡、讀過全人類所有書籍的「超級大廚」（例如 GPT-4o、Gemini 2.5、Claude 3.7）。
* **網頁版介面（如 ChatGPT 網頁）：** 就像是裝潢漂亮的「餐廳內用區」，讓你直接走進去跟服務生聊天。
* **LLM API：** 就像是餐廳的「外送專用窗口」。你不需要自己蓋廚房（買昂貴的顯示卡來訓練模型），只要透過程式寫一張「點餐單（Request）」遞進窗口，廚房做好後就會把「餐點（Response）」遞出來給你。

---

## 2. LLM API 的核心運作原理：「文字接龍」

很多人以為大腦在「思考」，但從技術底層來看，純粹的 LLM API 其實只做一件事：**超級精準的「機率文字接龍」**。

當你透過 API 傳送一句話：「今天天氣真好，我想去公園...」
1. **拆解（Tokenization）：** 模型會把這句話切成小碎片（稱為 **Token**，一個中文字大約佔 $1 \sim 2$ 個 Tokens）。
2. **預測下一個字：** 根據它過去讀過的幾千億篇文章，計算出下一個字出現的機率（例如：「散步」機率 $60\%$、「野餐」機率 $30\%$、「睡覺」機率 $1\%$）。
3. **吐出結果：** 它選了「散步」，然後再把「今天天氣真好，我想去公園散步」重新讀一遍，繼續預測下一個字，直到它覺得這句話結束為止。

---

## 3. 呼叫 API 時，我們都在傳遞什麼？

當工程師透過程式呼叫 LLM API 時，最基本只需要準備三個東西（就像填寫點餐單）：

| 欄位名稱 | 白話解釋 | 實際例子 |
| :--- | :--- | :--- |
| **API Key（金鑰）** | 你的「會員卡兼信用卡」，用來證明身份並計算費用（按 Token 數量計費）。 | `sk-proj-abc123xyz...` |
| **Model（模型名稱）** | 你要指定哪一位大廚來幫你做菜（有的聰明但貴，有的反應快又便宜）。 | `gemini-2.5-flash` 或 `gpt-4o` |
| **Prompt（提示詞）** | 你要交給大腦處理的具體任務或問題。 | `"請用一句話解釋什麼是黑洞。"` |

### 進階微調旋鈕：Temperature（溫度）
在呼叫 API 時，通常還會看到一個叫 `Temperature` 的參數（數值通常在 $0$ 到 $1$ 或 $2$ 之間），用來控制大腦的「創意程度」：
* **低溫度（如 $0.1$）：** 大腦會變得非常嚴謹、保守，每次都選機率最高的那個字。適合用來**寫程式、整理資料、回答事實**。
* **高溫度（如 $0.8$）：** 大腦會願意嘗試機率較低、比較冷門的字詞。適合用來**寫詩、發想創意、寫小說**。

## 4. 純粹 LLM API 的三大先天限制（為什麼還不是 Agent？）

雖然這個大腦很聰明，但如果你只停留在這個階段，會遇到三個非常明顯的瓶頸：

### ❌ 限制一：完全沒有記憶（無狀態 Stateless）
API 的每一次呼叫都是「獨立事件」。
* **第一通電話：** 你問 API：「我叫小明，我喜歡吃蘋果。」 $\rightarrow$ API 回覆：「你好小明，蘋果很健康！」
* **第二通電話（1秒後）：** 你問 API：「我叫什麼名字？我喜歡吃什麼？」 $\rightarrow$ API 回覆：「抱歉，我不知道你是誰。」
* **原因：** 為了節省伺服器資源，API 講完話就會立刻把剛才的對話忘得一乾二淨。

### ❌ 限制二：知識停留在過去（資訊孤島）
LLM 的知識全部來自於它「訓練完成的那一天」。如果你問它：「今天的台積電股價是多少？」或「明天台北會下雨嗎？」，它要嘛回答不知道，要嘛就會開始「一本正經地胡說八道（稱為 **AI 幻覺 Hallucination**）」。

### ❌ 限制三：只會動口，不會動手
它只能輸出「純文字」。它沒辦法幫你點擊網頁按鈕、沒辦法幫你把資料寫進 Excel 表格、也沒辦法真的幫你寄出一封 Email。它頂多只能「寫好一封 Email 的草稿文字」給你，最後還是得靠你自己複製貼上並按下發送。

---

## 🎯 本階段總結

**純粹的 LLM API** 就像是一顆通電的超級大腦，輸入文字，輸出文字。它是所有 AI 應用的核心引擎，但因為「沒有記憶」且「沒有手腳」，所以它只能被動地回答問題。
