# 🔄 第四階段詳解：啟動「思考與行動迴圈」（Agent Loop）

恭喜你來到最終章！在前面三個階段，我們已經為 AI 準備好了：
1. **大腦**（LLM API）
2. **記憶與靈魂**（對話歷史 + System Prompt）
3. **手腳**（Function Calling / MCP 工具）

但此時它還只是個「被動執行者」——你推一下，它動一下。為了讓它能獨立處理複雜、多步驟的任務，我們必須把所有積木放進一個**自動化迴圈（Agent Loop）**裡。這就是 **AI Agent（AI 代理人）** 真正誕生的瞬間！

---

## 1. 什麼是 Agent Loop（思考與行動迴圈）？

在寫程式的世界裡，這個迴圈的核心其實就是一個簡單的 **`while` 迴圈（只要任務還沒完成，就繼續做下去）**。

在 AI 領域，最經典的運作模式稱為 **ReAct（Reasoning + Acting，推理與行動）**。它讓 AI 像人類解決問題一樣，不斷重複三個動作：

1. **🧠 思考（Thought）：** 「我現在的目標是什麼？目前已知哪些資訊？下一步該做什麼？」
2. **🛠️ 行動（Action）：** 決定呼叫某個工具，並開出指令紙條。
3. **👀 觀察（Observation）：** 接收工具執行後回傳的結果，看看有沒有成功、有沒有遇到新狀況。

這個「思考 ➔ 行動 ➔ 觀察」的循環會一直轉動，**直到 AI 自己在「思考」階段判斷：「太好了，所有條件都達成了！」** 它才會跳出迴圈，向你回報最終結果。

---

## 2. 實戰演練：看 Agent 如何自己解決複雜問題

假設你對你的 AI Agent 下達了一個高難度指令：
> **「幫我查明天台北的天氣，如果降雨機率超過 $50\%$，就幫我把明天的『戶外攝影』行程取消，並寄信通知小美改期。」**

讓我們掀開蓋子，看看 Agent 內部的迴圈是如何一圈圈轉動的：

### 🔁 第 1 圈：先搞清楚天氣
* **🧠 思考：** 任務有條件限制，我必須先知道明天台北的降雨機率。
* **🛠️ 行動：** 呼叫工具 `查天氣(地點="台北", 時間="明天")`。
* **👀 觀察：** 工具回傳 `"明天台北陣雨，降雨機率 80%"`。

### 🔁 第 2 圈：根據結果做出決策
* **🧠 思考：** 降雨機率是 $80\%$，超過了 $50\%$ 的門檻！根據指示，我現在需要去取消行事曆上的行程。但我不知道那個行程的編號（ID），得先查詢一下。
* **🛠️ 行動：** 呼叫工具 `查詢行事曆(日期="明天")`。
* **👀 觀察：** 工具回傳 `"14:00 戶外攝影 (行程ID: #9527)"`。

### 🔁 第 3 圈：動手修改行程
* **🧠 思考：** 找到行程 ID `#9527` 了，現在把它刪除。
* **🛠️ 行動：** 呼叫工具 `刪除行事曆行程(ID="#9527")`。
* **👀 觀察：** 工具回傳 `"刪除成功"`。

### 🔁 第 4 圈：完成最後一項交辦事項
* **🧠 思考：** 行程取消了，還剩最後一步：寄信通知小美。我需要先查小美的 Email 地址。
* **🛠️ 行動：** 呼叫工具 `搜尋聯絡人(姓名="小美")`。
* **👀 觀察：** 工具回傳 `"mei@example.com"`。

### 🔁 第 5 圈：寄出通知信
* **🧠 思考：** 拿到信箱了，現在撰寫一封禮貌的改期通知信並寄出。
* **🛠️ 行動：** 呼叫工具 `寄送Email(收件人="mei@example.com", 主旨="明日戶外攝影改期通知", 內容="...")`。
* **👀 觀察：** 工具回傳 `"郵件已發送"`。

### 🏁 第 6 圈：任務完成，跳出迴圈！
* **🧠 思考：** 天氣查了、行程取消了、信也寄出了。所有步驟全部完成，不需要再呼叫任何工具！
* **🗣️ 最終回覆（跳出迴圈）：**
  > 「已為您處理完畢！因為明天台北降雨機率高達 $80\%$，我已經幫您取消了明天下午 2 點的『戶外攝影』行程，並寄信通知小美改期囉！」

## 3. 為什麼 Agent 這麼強大？（三大核心超能力）

透過這個迴圈機制，AI 擁有了傳統軟體（寫死的 `if...else` 程式）完全無法比擬的能力：

1. **動態規劃（不用寫死步驟）：**
   你不需要事先寫程式規定「第一步查天氣、第二步查行事曆」。只要把目標和工具給它，Agent 會自己決定先後順序。如果明天降雨機率只有 $10\%$，它會在第 2 圈就直接跳出迴圈跟你說「天氣很好，行程照舊」，完全不會去動你的行事曆！
2. **自我修正（遇到錯誤會轉彎）：**
   如果第 4 圈搜尋「小美」找不到人，Agent 在「觀察」到錯誤後，會在下一圈自己「思考」：「通訊錄找不到小美，那我去搜搜看過去的 Email 往來紀錄裡有沒有她的信箱！」——它具備了**試錯與隨機應變**的能力。
3. **可擴展的記憶與反思：**
   在更進階的 Agent 設計中，迴圈裡還會加入「自我檢查（Reflection）」機制（例如寫完程式碼後，自己先跑一次測試，發現報錯就自己修改，直到測試通過才交給你）。

## 4. ⚠️ 開發 Agent 時的「安全煞車」機制

既然是個 `while` 迴圈，工程師在設計時一定會加上兩道安全鎖，防止 AI 失控：

* **最大步數限制（Max Iterations）：**
  規定「最多只能轉 $10$ 圈」。萬一 AI 遇到死胡同（例如網路斷線一直重試），到了第 $10$ 圈就會強制踩煞車停止，避免它無限循環燒光你的 API 費用。
* **人類確認機制（Human-in-the-loop）：**
  對於高風險動作（例如：轉帳、刪除重要檔案、對外發送公開貼文），我們會在工具執行前設定「暫停」，跳出視窗問你：「AI 準備要寄出這封信了，你同意嗎？」等你按下確認，迴圈才會繼續往下走。

## 🎉 總結：從零到一的完整拼圖

回顧這四個階段，你已經徹底掌握了現代 AI Agent 的核心建構原理：

$$\text{AI Agent} = \text{LLM（大腦）} + \text{Memory \& Prompt（記憶與人設）} + \text{Tools（手腳）} + \text{Agent Loop（自主思考迴圈）}$$

1. **純粹 LLM API：** 只能一問一答的博學顧問。
2. **加上記憶與人設：** 變成記得上下文、懂規矩的聊天機器人。
3. **接上工具（Function Calling / MCP）：** 學會開出指令紙條，讓外部程式幫忙查資料、辦事。
4. **啟動思考與行動迴圈（Agent Loop）：** 賦予 AI 自主規劃、觀察結果、不斷推進直到任務達成的靈魂！
